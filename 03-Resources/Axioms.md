# 🏛️ Axioms

Axioms are the small set of foundational beliefs everything else in this vault
derives from. They change rarely, if ever. Most vaults need only a handful.

An axiom isn't a decision (a choice made at a point in time) or a principle (a
derived behavioral rule) — it's the thing you'd say if someone asked "what do you
actually believe about how this system should work, underneath all the specific
choices?"

## Why this file (not a folder)

Unlike Decisions and Principles — which accumulate over time — axioms should stay
few and stable. A single file keeps them visible at a glance instead of scattered
across many notes. If this file starts growing past 8-10 entries, that's a sign
some of them are actually principles (derived rules) rather than true axioms
(foundational beliefs), and should move to [[03-Resources/Principles/README|Principles]].

## How to write one

One sentence stating the belief, then a short paragraph on what it implies in
practice. Example:

> **Implement locally first, upload only on explicit instruction.**
> Changes to the public template are made and verified in the working tree first.
> Nothing gets staged, committed, or pushed to GitHub until the user explicitly
> says so — even when a change is clearly correct and tested. This protects
> against shipping something the user hasn't actually reviewed yet, and it respects
> that the template is public-facing in a way the local vault isn't.
